# TRAM Helm Chart

Deploys `tram manager`, which runs every `Engine` resource as a Deployment (or StatefulSet) of TRAM instances in the Engine's namespace, and the `Engine` and `Stream` CRDs. Engines and Streams are resources you create, not part of the chart; see [Engines](../../internal/adapters/k8scrd/README.md#engines) and the examples in [`examples/k8s/examples/`](../../examples/k8s/examples/).

## Install

Every release publishes the chart to `oci://ghcr.io/go-tram/charts/tram`, with the release's version as both the chart version and the app version:

```bash
helm install tram oci://ghcr.io/go-tram/charts/tram --namespace tram-system --create-namespace
```

Without `--version`, Helm installs the latest release; add e.g. `--version 0.0.19` to pin one.

The chart is attached to the [GitHub Release](https://github.com/go-tram/tram/releases) as `tram-<version>.tgz` as well. From the repository, the chart has the version `0.0.0` and deploys the image `latest`, which is the latest release:

```bash
helm install tram charts/tram --namespace tram-system --create-namespace
```

Then create an Engine and a Stream that runs on it:

```bash
kubectl apply -f examples/k8s/examples/engine.yaml
kubectl wait engine/demo --for=condition=Ready
kubectl apply -f examples/k8s/examples/otlp_debug.yaml
kubectl get engines,streams
```

The chart deploys `ghcr.io/go-tram/tram` in the chart's `appVersion`, the release's version, by default. If the package is private, pass a pull secret with `imagePullSecrets`; for an image of your own, set `image.repository` and `image.tag`. The manager runs the Engines' instances, and their drain Jobs, with the same image, unless `manager.engineImage` names another; an Engine's own `image` overrides both.

## What It Creates

| Resource | Name | Purpose |
|----------|------|---------|
| Deployment | `<fullname>` | `tram manager`, two replicas with leader election by default; the lease is in the release's namespace |
| ServiceAccount | `<fullname>` | The manager's identity |
| ClusterRole | `tram-manager` | What the manager may do: run Engines (Deployments, StatefulSets, Services, ServiceAccounts, …) and label Streams |
| ClusterRoleBinding | `<fullname>` | Binds `tram-manager` to the manager's service account. With `manager.watchNamespaces`, a RoleBinding of the same name in each of these namespaces and in the release's namespace instead, so the manager has no rights elsewhere |
| PodDisruptionBudget | `<fullname>` | Keeps one replica of the manager running while nodes are drained; only with more than one replica |
| PodMonitor | `<fullname>-engines` | Optional: lets the Prometheus operator scrape `/metrics` of every Engine's instances |
| ClusterRole | `manager-role` | What the Engines' instances may do: read their Streams, Secrets and ConfigMaps. The manager binds it to the service account of every Engine, in the Engine's namespace, and may bind no other role |
| CustomResourceDefinitions | `engines.io.tram.core`, `streams.io.tram.core` | The `Engine` and `Stream` resources; kept on uninstall |

`<fullname>` is the release name, with `-tram` appended unless the release name contains `tram`; `fullnameOverride` replaces it. The ClusterRoles and CRDs are cluster-wide and have fixed names, so install the chart once per cluster.

## Generated Templates

The CRDs in [`crds/`](crds/) and the ClusterRoles in [`templates/tram-manager/rbac/`](templates/tram-manager/rbac/) are generated by controller-gen from the `//go:generate` directives in [`internal/adapters/k8scrd/operator.go`](../../internal/adapters/k8scrd/operator.go), which write the same files to [`manifests/`](../../manifests/). Do not edit them by hand; run `task generate`. The other templates are written by hand.

## CRDs

The CRDs are in Helm's [`crds/`](crds/) directory, so Helm handles them apart from the templates: `helm install` creates them if they do not exist yet, while `helm upgrade` neither creates nor updates them and `helm uninstall` leaves them. `helm template` leaves them out unless you pass `--include-crds`.

If you manage the CRDs yourself, e.g. from [`manifests/crds/`](../../manifests/crds/), install the chart without them with `--skip-crds`, or `skipCrds: true` in the Helm source of an Argo CD Application.

Since `helm upgrade` does not touch the CRDs, apply the ones of the new version before upgrading the chart, server-side, as they are too large for a client-side apply:

```bash
helm show crds oci://ghcr.io/go-tram/charts/tram --version <version> | kubectl apply --server-side --force-conflicts -f -
helm upgrade tram oci://ghcr.io/go-tram/charts/tram --version <version> --namespace tram-system
```

## Uninstall

```bash
helm uninstall tram --namespace tram-system
```

This removes the manager and its RBAC but keeps the CRDs, and with them every Engine and Stream of the cluster and the Engines' Deployments and StatefulSets, which run on without a manager until you install it again. To remove everything, delete the Engines first, so the manager drains their buffers and cleans up, then the CRDs:

```bash
kubectl delete engines --all -A
kubectl delete crd engines.io.tram.core streams.io.tram.core
```

## Values

| Key | Default | Description |
|-----|---------|-------------|
| `replicaCount` | `2` | Replicas of the manager; with leader election, one works at a time |
| `image.repository` | `ghcr.io/go-tram/tram` | Image of the manager |
| `image.tag` | `""` | Tag of the image; defaults to the chart's `appVersion` |
| `image.pullPolicy` | `IfNotPresent` | Pull policy of the image |
| `imagePullSecrets` | `[]` | Secrets to pull the manager's image, e.g. `[{name: ghcr}]` |
| `nameOverride` | `""` | Replaces the chart name in the resource names |
| `fullnameOverride` | `""` | Replaces the full name of the resources |
| `manager.watchNamespaces` | `[]` | Namespaces whose Engines and Streams the manager handles; empty for all. Set, the manager gets RoleBindings in these namespaces only |
| `manager.engineImage` | `""` | Image of the Engines' instances and drain Jobs; defaults to the manager's image |
| `manager.leaderElect` | `true` | Let only one replica work at a time; leave it on with more than one replica |
| `manager.logLevel` | `info` | Log level: `debug`, `info`, `warn` or `error` |
| `manager.extraArgs` | `[]` | More arguments for `tram manager` |
| `manager.extraEnv` | `[]` | Environment variables of the manager's container |
| `serviceAccount.create` | `true` | Create the manager's service account |
| `serviceAccount.name` | `""` | Name of the service account; defaults to the full name |
| `serviceAccount.annotations` | `{}` | Annotations of the service account |
| `podAnnotations` | `{}` | Annotations of the manager's pods |
| `podLabels` | `{}` | Labels of the manager's pods, besides the chart's |
| `podSecurityContext` | non-root as `65532`, `RuntimeDefault` seccomp | Security context of the pods; the image's user `nonroot` is `65532`, which `runAsNonRoot` needs as a number |
| `securityContext` | no privilege escalation, read-only root file system, no capabilities | Security context of the container |
| `resources` | requests `100m` CPU and `128Mi`, limit `256Mi` | Resources of the container |
| `priorityClassName` | `""` | Priority class of the pods |
| `nodeSelector`, `tolerations`, `affinity`, `topologySpreadConstraints` | empty | Scheduling of the pods |
| `podDisruptionBudget.enabled` | `true` | Create a PodDisruptionBudget for the manager when `replicaCount` is above 1 |
| `podDisruptionBudget.maxUnavailable` | `1` | Replicas of the manager a disruption may take down |
| `engineMetrics.podMonitor.enabled` | `false` | Create a PodMonitor for the Engines' instances; needs the Prometheus operator's CRDs |
| `engineMetrics.podMonitor.interval` | `30s` | Scrape interval |
| `engineMetrics.podMonitor.labels` | `{}` | Labels of the PodMonitor, e.g. what your Prometheus selects on |
