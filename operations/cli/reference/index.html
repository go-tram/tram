Command Reference¶

Every command of the tram binary with its flags, as --help shows them. As the kubectl plugin kubectl tram, the binary has the commands that work with streams and stream files, and Kubernetes is their default target; see The tram CLI.

tram¶

TRAM receives, processes and forwards OpenTelemetry logs, metrics and traces

TRAM receives, processes and forwards OpenTelemetry logs, metrics and traces in streams: a source, stages and sinks, configured through an API, files or Kubernetes resources.

The binary runs TRAM, and is the CLI to work with its streams: tap and manage the streams of a running instance through its admin API, or check stream files without one.

tram [flags]

Flags

  -h, --help               help for tram
      --log-level string   Log level: debug, info, warn or error (default "info")

Commands: tram completion, tram components, tram drain, tram manager, tram server, tram stream, tram tap, tram test, tram validate

tram drain¶

Deliver what the buffer queues of an Engine's volume hold, then exit

Drain runs only the Streams of an Engine that read from a buffer: their sources deliver what the queue files in the data directory hold, to the sinks of those streams. Every other Stream is treated as suspended, so nothing is written to the volume any more. Drain exits once every queue file is empty or holds only entries older than their max_age, so a volume without an instance can be removed without losing data. tram manager runs it as a Job for such volumes.

tram drain [flags]

Flags

      --data-dir string           Directory holding the buffer queue files
      --engine string             Engine whose Stream resources are drained
  -h, --help                      help for drain
      --kubeconfig string         Kubernetes config file
      --watch-namespace strings   Namespaces whose Stream resources are drained, comma-separated (default all)

Inherited flags

      --log-level string   Log level: debug, info, warn or error (default "info")

tram tap¶

Show the events passing a running stream

Show the events passing a running stream of a TRAM server.

The server hands out copies of the events at the source, at every stage and at every sink, or at the one component --component names: what a source or stage passed on, and what a sink received and whether it took it. The stream is not changed and never waits for the tap: events the tap cannot take in time, or beyond --rate, are dropped and reported.

The tap keeps running when the stream is replaced, and ends when the stream is deleted or the tapped component is removed. It talks to the admin API of the server (tram server --admin-endpoint, localhost:50052 by default).

In Kubernetes, the stream of a Stream resource is its name, in the namespace of -n or the kubeconfig, or .. --kube taps every pod of the Engines the stream's Stream resource names, from the kubeconfig's current context; --engine or --selector name the pods instead. Every pod runs the stream with its share of the data. The CLI forwards a port to each pod, as kubectl port-forward does, follows scaling and rollouts, and shows the pod of every event. --rate and --limit count for all pods together.

tram tap <stream> [flags]

Examples

  tram tap my-stream
  tram tap my-stream --component loki --rate 10
  tram tap my-stream --output json --limit 100 > events.ndjson
  tram tap logs --kube -n observability      # the Stream resource logs
  tram tap my-stream --engine telemetry -n observability

Flags

      --admin-endpoint string          Admin API of the TRAM server (env TRAM_ADMIN_ENDPOINT, default localhost:50052)
      --admin-port int                 Kubernetes: port of the admin API in the pods (default the Engine's, or 50052)
      --as string                      Username to impersonate for the operation

tram test¶

Run the test cases of a stream file locally

Run the test cases of a stream file locally.

The file holds either a bare stream object or a file sync file that wraps it in {"stream": {...}}, like the examples in examples/config/.

The stream is loaded into its own in-memory tree: the source is replaced by a test source that emits the test inputs and every sink by a capture sink, so no external system is contacted. Stages are the real stages and process the events. References in stage specs are resolved from the secrets file, keyed "/".

tram test <stream.json> [flags]

Flags

  -h, --help             help for test
      --secrets string   JSON file with secret values keyed "<name>/<key>" for references in stage specs

Inherited flags

      --log-level string   Log level: debug, info, warn or error (default "info")

tram validate¶

Check stream files without running them

Check stream files without running them: their format, the stream name, that the stream is a tree, and the spec of every component.

Sources and sinks are checked without contacting anything: a broker component checks its options but does not connect, an OTLP source opens no port. Stages are built and stopped again, as in tram test, so an encryption stage with the stackit-kms driver contacts the KMS. A directory is read like the file sync reads it: its *.json files, not its subdirectories. Two files with the same stream name are an error.

References like {"valueFrom": {"secretKeyRef": ...}} are resolved from the secrets file, keyed "/"; without one, a reference fails the check.

tram validate <file or directory>... [flags]

Examples

  tram validate config/
  tram validate stream.json --secrets secrets.json

Flags

  -h, --help             help for validate
      --secrets string   JSON file with secret values keyed "<name>/<key>" for references in component specs
